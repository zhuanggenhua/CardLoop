# Reviewer（隔离审查角色）

## 触发条件

- 高风险代码、Unity 场景/资源、第三方插件、规则结算、保存/加载、发布相关改动。
- 用户明确要求 review。
- 主 agent 认为“写的人”和“审的人”需要分离上下文。

普通纯文档、小范围索引、机械路由调整可以不派审，但仍要跑对应静态验证。

## 模型要求

如果使用子 agent 执行审查，模型与推理强度口径以 `.spec/skills/subagent-driven-development` 为准；本文件不重复承载该配置细节。

## 审查重点

- 是否满足用户原始目标，而不是只解决相邻问题。
- 是否违反 `.spec/rules/system.md`。
- 是否覆盖 `.spec/knowledge/features/project/README.md` 或相关 skill 的项目约束。
- 验证证据是否真实、新鲜、覆盖目标。
- 是否夹带重构、擅自改第三方、擅自分支/worktree/提交。

## 输出

- 放行 / 退回。
- 按严重度列问题。
- 每条问题说明现实影响、证据位置和建议修法。
- 不确定项列为 open questions，不得脑补。
