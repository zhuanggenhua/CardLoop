# 开发与规范治理流程

## 前提门禁

动手前提和多参考源设计裁决的唯一正文是 [`.spec/skills/before-you-code/SKILL.md`](../../skills/before-you-code/SKILL.md)。本文件只保留流程层路由：任何代码、配置、资源、规范、插件级或架构级改动，先进入 `before-you-code` 锁定问题对象、真相来源、目标入口/环境和验收口径；参考工程任务还要在该 skill 中完成设计裁决标准。

## 参考模块吸收门禁

参考模块的“吸收完成”指玩家可见能力已经由当前项目新正式框架接管，不是保留参考工程的类、字段和目录，也不是把多个参考实现拼成一套结构。

结构排除不等于效果排除。参考实现职责冲突、规则写死或架构较差，只能证明旧结构不能直接接管；只要对应玩家可见效果仍属于本游戏目标，替换清单必须写明它在 Gameplay / GameCore / EX-GAS / UI / 角色 / 存档或联机职责中的等效实现路径，并用新正式链路验证。只有用户明确作出产品排除裁决，才允许不复现，并必须写清排除理由。

等价目标默认覆盖玩家可见的触发条件、过程结果、规则结算、状态变化、操作结果和必要反馈，不默认复制参考工程的 UI 结构、旧组件链或皮肤实现。参考 UI 先用于识别功能入口、信息层级和必要反馈；新框架 UI 必须完整承载同等功能、保持可读可操作并符合 CardLoop 自身设计。

但“不是 UI 外观复制”不能被解释成“表面和动画不用对账”。当用户目标是“用当前框架吸收参考模板业务效果”，且参考工程的卡面、材质、布局、图标、粒子、音效、进度条、命中反馈、拖拽、移动、受击、投射物或镜头动画本身承载玩家可见效果时，必须建立表面 / 动画对照表：列出参考 Prefab / 材质 / 脚本证据、当前实现证据、差异、是否保留和替代路径。

只有表面 / 动画对照表里的对应项已经匹配、或由用户明确裁决为产品排除项，才允许说该玩家可见效果已等价吸收。自动化规则测试、源码映射或机制参数一致，不能越权证明视觉表面、手感动画或最终玩家画面一致。

### 先判定是否值得保留，不以复制或重写为默认

“正式代码不得依赖 StackCraft 的旧运行时入口”不等于“模板里的每段代码都必须从零重写”；同样也不等于应该优先复制模板。每个独立职责切片在写代码前，必须先判断模板实现是否满足 CardLoop 的对象边界、唯一真相、作者源、输入、资源、存档、联机与 Mod 约束，再明确选择下列一种处理方式：

1. **整体保留 / 迁入**：只有源码本身已经是可接受的设计，且移走命名空间、程序集或少量项目引用后仍只有一个正确 owner，才保留其代码、Prefab 或作者工具。
2. **提取并改造**：模板的算法、数据结构或编辑器体验有价值，但外层职责不正确。只迁入可分离的部分，并让当前项目的正式对象拥有状态。
3. **吸收问题与验收结果，自行实现**：模板能证明一项玩家需要的能力，但实现依赖旧单例链、固定场景、旧输入、第二套内容/存档真相或直接副作用。此时应以当前项目的正式结构实现等效能力，而不是复刻模板结构。
4. **排除**：不属于当前产品目标，或已经被现有正式职责更完整地覆盖。

选择“整体保留 / 迁入”或“自行实现”前，都必须写出模板对应代码、保留或不保留的具体依据，以及当前正式 owner；“这是模板已有代码”“这是我们自己的框架”“重新写更干净”都不是充分理由。

`FoundationTest` 只承担每个已裁决模块的一条真实玩家链路。它可以随模块吸收继续扩展，用来证明当前项目的对象和交互能够覆盖模板选择保留的能力；它不是 StackCraft 旧脚本、旧场景结构或旧单例链的复制品。若用户目标或模块裁决要求吸收 StackCraft 玩家可见效果，则静态卡面、材质、布局、参数和动画必须按参考源码 / Prefab / Material 逐项复刻；截图只用于发现偏差，不能替代源码参数对账。

当用户明确要求“一比一复刻”“参数都有”“不是类似效果”时，验收默认进入源码参数闭包模式：先把参考 Prefab、Material、Shader、Mesh、字体、Collider、Transform、动画曲线 / 时长和资源 GUID / fileID 中承载玩家可见效果的参数列为真相源，再证明当前项目正式作者源或生成器写出了等价参数。只有代码、资源和序列化回读都对齐后，截图才可用于最终外观诊断；不得用截图微调、人工观感或“已经很像”替代参数闭包。

每个 StackCraft 一级模块必须按以下顺序收口：

1. 先列功能裁决：逐项区分“明确吸收的玩家可见功能”“只作为问题证据/体验参考”“明确排除的旧功能”。参考源码中存在的类、枚举、字段和未被真实内容使用的能力，不能自动进入吸收清单。
2. 再确定唯一架构：从当前游戏需求、现有正式职责、原生能力和成熟框架边界推导一条完整实现；参考工程只提供证据，不允许按来源各保留一块结构。
3. 使用新框架实现：正式代码不得依赖 StackCraft 运行时命名空间、旧单例、固定资源路径或旧场景入口。临时素材可以复用，但职责、状态和执行链必须归当前项目。
4. 在统一测试场景验收：默认追加到 `FoundationTest`；只有场景隔离确有必要时才建立专项测试场景。测试必须覆盖本模块明确选择吸收的同等玩家可见功能，以及新架构特有的职责边界。
5. 通过后进入下一一级模块：自动化测试、运行日志、场景状态或必要的人工交互证据必须能回到功能裁决逐项对账。只完成子模块文档、接口、静态结构或单元测试，不能越权宣布整个一级模块已吸收完成。

“实现相同功能”只要求功能和交互结果等价，不要求保留参考工程的结构。明确排除的自动触发、固定场景名、单例链、直接副作用、枚举扩展限制等旧行为，应在测试中证明没有进入正式链路，而不是为了表面一致重新实现。

## 执行边界

### Codex 宿主环境工具门禁

- 动手前必须先按当前会话宿主选择工具：Codex CLI / TUI 环境使用 `shell_command` 读取终端、文件状态、依赖探测和本地命令结果；Codex App / 桌面宿主环境才允许在确有需要时使用 `codex_app.*` 读取 App 终端、导航线程或加载工作区依赖。
- 不得把调用失败当成环境探测方式。若已知当前处于 CLI / TUI，禁止调用 `codex_app.*` 这类动态 App 工具；若不确定宿主环境，先通过当前上下文、可用工具清单、普通 shell 命令或用户说明判断，再选择工具。
- 如果某个工具返回 `Dynamic tool calls are not available in TUI yet.`，说明当前宿主不支持该动态 App 工具；必须立即停止重复调用，记录为工具环境限制，并改用当前宿主可用的正式工具链。不得把它当作项目代码、Unity 或测试失败。
- 需要 Unity 验证时仍先走 `.spec/tools/unity-verify.mjs` guard；不得因为 App 工具不可用就绕过 Unity 验证门禁。
- 根 `AGENTS.md` 是入口，只放指针，不再堆项目细节。
- `.spec` 是规范、knowledge、skill 和 agent 的唯一权威源。
- `.spec/knowledge/features/project/` 是当前项目知识库正式入口；废弃目录不得作为规范入口继续引用。
- `openspec` 承载 proposal/change/spec，不混进 `.spec/decisions`。
- 项目 skill / agent 的落点、宿主发现适配入口和 `.codex/skills` 禁用口径，由 [`.spec/skills/spec-steward/SKILL.md`](../../skills/spec-steward/SKILL.md) 统一承载；本文件不重复写宿主目录规则。
- 参考工程接入或插件级抽象不得先写实现再补证据；如果外部参考路径尚未读取、关键入口尚未定位，必须停在“前提未锁定”，不能用“先做一个通用版本”代替参考裁决。

## LumioAgent 吸收边界

采用：

- `.spec` 结构分层。
- `spec-steward` 维护规范落点。
- `lessons.md` 作为反复错误升级池。
- “完成声明必须有验证证据”的收口门禁。
- “主 Agent 调度、skill 是方法、`.md` 是规则”的结构思想。
- 宿主发现目录已按 Git symlink 收口；当前执行口径见 `spec-steward`。

不采用：

- 默认创建或使用 git worktree 的流程。
- 未经用户确认的分支、提交、发布、PR 流程。
- 所有生产代码都必须严格 TDD 的一刀切规则。
- “设计文档必须提交”的默认动作。

## Git 与提交

- 不使用回滚/撤销历史操作。
- 不擅自创建、切换、重建或删除分支、tag、worktree。
- 不主动提交、不推送，除非用户当轮明确允许。
- 工作区已有无关改动时，只触碰本轮目标文件。

## 知识沉淀

新增规则、修改规范、新建/迁移 skill、任务卡和决策记录的落点治理，唯一正文是 [`.spec/skills/spec-steward/SKILL.md`](../../skills/spec-steward/SKILL.md)。本文件只保留流程要求：先判断落点，再同步索引；发现多个文档承载同一口径时，收口到一个权威文档，其它位置改成路由或证据说明。

## 结构校验

`.spec` 结构、索引、skill 或 agent 变化后，运行：

```powershell
node .spec/tools/spec-lint.mjs
```

该脚本只检查规范结构，不启动 Unity、不修改资产。
