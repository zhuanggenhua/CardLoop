# 运行时实现边界

本文件回答“正式实现应该把真相放在哪里、运行时代码能做什么、哪些补法会制造第二套真相”。写运行时逻辑、UI 绑定、资源加载、依赖入口、性能敏感路径或配置字段前必须查。

## 配置真相

- 同一条用户可见行为里，同一语义的参数、完成边界和最终消费入口只能有一个权威来源；如果“改了 A 还要同步改 B 才生效”，默认视为双真相或边界设计问题。
- Prefab、场景、ScriptableObject、Material、Animator、Volume Profile、输入配置、资源清单、表格、JSON、Luban 或脚本等作者源如果已经能表达某个静态事实，正式修复必须回到对应作者源或配置源，不用运行时代码再覆盖一份。
- 作者源选择先看现实生产方式和消费入口，不按“必须用 SO”或“必须不用 SO”裁决：ScriptableObject 适合 Unity 内作者工具、Inspector 可视化、资源引用、内置内容和需要随 Unity 资源包构建的内容；表格 / Luban 适合大批量数值、规则矩阵和非 Unity 策划协作；JSON / YAML 适合外部 Mod 包、文本可 diff 和非 Unity 工具链；脚本只适合受控行为扩展和复杂事件编排，接入前必须先有权限、版本、存档、联机和安全边界。
- 同一事实只能有一个主作者源。不得因为未来支持 Mod、关卡编辑器或联机就默认否定 SO，也不得因为当前 Unity 内编辑方便就把大批量数据、外部创作者配置或脚本行为强塞进 SO；只有说明目标作者、编辑环境、运行时消费入口、构建 / 发布链路和验证方式后，才允许改换或新增作者源。
- 当同一功能同时存在 Prefab 默认值、场景实例 override、运行时代码默认值或缓存值时，必须说明哪一层是权威编辑入口、其余层为什么存在，以及优先级顺序；说不清就不能继续堆参数。
- 可由权威真相直接推导的派生值、缓存、索引和中间表示不得要求作者手动维护第二份；正式链路负责自动生成、刷新或校验。

## 首帧同步

- UI、表现组件或运行时对象同时持有“序列化出来的当前视图状态”和“运行时逻辑状态”时，首次打开必须显式同步一次视图。
- `Image.fillAmount`、缩放条、显隐态、文本缓存、动画进度、按钮可交互态等字段不能依赖“后续同值 setter 会触发刷新”。
- 正式同步入口可以是 `Awake`、`OnEnable`、`Show/Open`、`Apply`、聚合根状态提交或其它权威入口，但必须唯一且可回读。

## 依赖入口

- 正式依赖入口必须满足四个条件：来源可回读、权威载体唯一、生命周期清楚、缺失时暴露错误。
- 允许入口包括：序列化字段、Prefab 字段、场景实例 override、Inspector / UnityEvent / AnimationEvent 引用、显式注入、Bootstrap / Registry、ScriptableObject 配置、集中资源清单、项目已有服务入口、工厂 / Provider / Resolver、同对象或父级组件契约。
- 禁止把 `FindObjectOfType`、`FindObjectsOfType`、`GameObject.Find`、`Transform.Find`、`FindWithTag`、`Camera.main`、按名字递归扫描或标签全局查询写成正式依赖获取。
- 命中对象解析和依赖获取必须分型：从碰撞、射线、触发对象上读父级业务组件是命中解析；查场景服务、相机、UI、Animator、Renderer、Prefab、配置资产是依赖获取，必须走正式入口。
- 唯一场景对象、正式系统入口和进程级运行服务只能在正式 owner 处配置一次。主相机、正式输入、资源系统、事件系统、场景系统、GAS 初始化和同类唯一职责不得在多个玩法组件上重复暴露手填引用。

## 缺失处理

- 服务、资源、组件、配置、事件目标或作者源缺失时，正式链路必须中文报错并停止当前子链路，不能自动创建、运行时补组件、换默认资源、静默跳过或返回假成功。
- 内部不变量被破坏时应尽早抛出明确异常；正常业务拒绝、外部输入失败、联机过期命令和可恢复依赖故障才使用显式拒绝、重试或恢复机制。
- 诊断探针只能用于取证，必须有开关、期限或清理点；探针结果不能冒充正式修复。

## UI 与表现

- 正式玩家可见 UI 应优先落成 Prefab、场景对象或正式 UI 框架入口，让层级、尺寸、Sprite、字体、文案和默认态可被作者检查。
- 业务运行时代码只负责显隐、交互、文本映射、状态同步和规则消费；不得用 `new GameObject`、运行时 `AddComponent`、临时克隆层级或脚本拼 UI 树来替代正式 UI 资源。
- 正式 UI 的显隐方式由真实消费链决定。常驻宿主可用 `CanvasGroup` 控制显示、输入和射线；需要外部 SDK、曝光、点击、加载或生命周期回调的 UI 必须暴露显式显示 / 隐藏事件。
- 纯视觉、样式、显隐和文案任务不得偷改业务语义；如果必须改规则、状态机或结算，应先单独说明并获得授权。

## 资源与渲染

- Shader、Material、Prefab、Profile、配置资源等应优先通过序列化引用、集中配置、资源系统或构建清单纳入依赖，不把运行时字符串查找当成权威依赖管理。
- 如果第三方 API 或运行时材质构造确实需要 `Shader.Find`、字符串路径或名字查找，同一轮必须补齐唯一明确的构建保留入口，例如序列化直引、预加载清单、Addressables / YooAsset 收集项或等价配置。
- 场景地址选择器、编辑器场景菜单和正式场景快照只能收项目场景根下的正式场景；参考模板、插件 Demo、Recovery 和第三方样例场景不得自动进入正式 YooAsset 场景地址或菜单入口。
- Gameplay 运行时代码不得新增第二套 YooAsset 地址引用或加载封装；当前资源加载职责归属是 `GameCore.ResourceSystem` / `SoftAssetReference`。若该职责不满足 Mod、关卡编辑器、联机或内容包需求，先重构正式资源职责，不并行保留薄包装或第二加载入口。
- 修改材质、Shader、描边、后处理或粒子表现前，必须先锁定具体异常对象、实际消费材质 / Shader、关键序列化参数和目标出图语义；不得用单个对象现象改写基础 shader 的全局语义。

## 性能边界

- 涉及 `Update` / `LateUpdate` / `FixedUpdate`、高频 UI、批量生成 / 回收、资源加载、动画 / 特效驱动、列表构建、战斗数值循环或其它热路径时，方案阶段必须先判断 CPU、GPU、内存、GC 和峰值抖动。
- 热路径禁止默认引入新集合、字符串拼接、装箱、普通 LINQ、反射、闭包捕获、重复 `GetComponent`、重复运行时搜索、频繁 `Instantiate/Destroy` 等可预见开销。集合查询另按 [`code-style.md`](code-style.md) 的 ZLinq 规则执行。
- 缓存、对象池、共享材质、预加载清单和降级开关也必须有明确 owner 与失效边界，不能为了优化平行造第二套资源或状态入口。
- 没有目标平台量化证据时，汇报只能说“已做静态收口 / 仍需目标平台验证”，不能声称性能问题已完全解决。

## 新增文件边界

- 一次新增两个及以上代码文件前，必须说明每个文件的职责、生命周期和为什么不能并入现有入口。
- 能扩现有正式组件、现有 Shader、现有管理器或现有作者源时，不新增包装层。
- 确认旧方案已被新方案替代后，要清理旧字段、旧组件、旧挂点、旧分支和旧文档描述；不得让两套路径长期并存。
