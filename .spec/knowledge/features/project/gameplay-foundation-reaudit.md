# Gameplay 地基重审摘要

本文件只保留当前仍有效的重审结论；历史重审记录不在工作区另设中间文档，追溯以 git 历史为准。

## 当前结论

- 旧文档中“模块已完成”“架构已收口”“最佳实践”的表述统一降级为“当时功能切片已验证”。
- 重审对象不是文件数量，而是状态 owner、唯一写入口、生命周期、失败语义、保存 / 同步点和玩家可见结果。
- 当前模型以 `ScenarioDirector -> ScenarioRun -> QuestLog / Tabletop` 为主要 Gameplay 单局聚合候选；进程级 GameCore 服务不得持有具体单局业务状态。
- `ActionDefinition`、候选、请求和行动实例是不同生命周期，不是天然重复；是否拆 / 合并必须看真实状态和调用方。
- EX-GAS 是属性、效果、技能和标签的唯一正式能力来源；Gameplay 不再造第二套属性 / 伤害 / 技能系统。

## 模块裁决摘要

| 模块 | 当前可保留 | 后续边界 |
|---|---|---|
| 内容定义 / 加载 / 校验 | `ContentId`、SO 作者源、EX-GAS 标签引用、内容索引候选 | 剧本包、Mod 覆盖和作者工具等真实需求出现后再扩展，不建第二目录。 |
| 启动 / 系统协作 | GameCore 进程级基础设施入口 | 单局状态归 Gameplay 单局聚合，不回到多个进程级系统并列持有。 |
| 可堆叠卡牌 | 深牌桌聚合、卡牌快照、表现投影 | 不扩成地点 / 工位 / UI 的万能对象模型。 |
| 行动 / 配方 / 牌桌进度 | 行动作者聚合、候选 / 请求 / 实例阶段、原子提交 | 结果扩展等第二个真实状态提交方出现后再定正式扩展接口。 |
| 剧本 / 回合 / 任务 | 单局剧本聚合与任务日志事实分发 | 新事实由真实 owner 接入，不建空 Encounter / Objective 顶级系统。 |
| EX-GAS / 战斗 | 角色卡唯一 ASC、牌桌战斗生命周期、GAS 效果入口 | 战斗存档、联机复制、完整数值和回放另行裁决。 |

## 后续重构边界

- 先完成文档收口和文件级归属审查，再动代码。
- 不用旧测试、旧截图或旧完成记录证明当前架构已经正确。
- 不为理论未来需求新增空接口、占位系统、防护表或兼容层。
- 若一个模块删除后复杂度不会重新分散到多个调用方，它是浅包装，优先删除或并回真实 owner。
