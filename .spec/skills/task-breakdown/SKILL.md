# Task Breakdown（任务拆解）

## 何时使用

- 目标太大或太模糊，不能直接动手。
- 涉及多个模块、多个文件集或多个验收入口。
- 需要区分可并行和必须串行的工作。
- 需要把任务交给子 agent 或后续会话。

## 拆解步骤

1. 锁定四项前提：对象、真相来源、目标环境、验收口径。
2. 切职责：每张卡只解决一件事。
3. 列文件集：同一文件集重叠的任务必须串行。
4. 写验收标准：每张卡都能独立判断是否完成。
5. 标依赖：有依赖的任务明确顺序。
6. 必要时写入 `.spec/tasks/<slug>.md`。

## 禁止

- 不为并行而创建 worktree、分支或 tag，除非用户当轮明确许可。
- 不把计划文件当成任务完成本身。
- 不把任务卡堆进 `.spec/knowledge/features/project` 长期知识库。
