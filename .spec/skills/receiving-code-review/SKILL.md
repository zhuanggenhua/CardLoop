# Receiving Code Review（处理审查反馈）

## 流程

1. 完整读取反馈。
2. 用自己的话确认每条反馈对应的现实问题。
3. 回到代码、资源、文档或测试证据核实。
4. 判断是否适用于当前项目和用户既有决策。
5. 一次处理一条，处理后验证。

## 口径

- 用户反馈默认优先，但范围不清时必须问最小问题。
- 外部 reviewer 反馈必须核实，不得盲改。
- 与用户此前决策冲突时，先说明冲突并请用户裁决。
- 不使用“你说得完全对”这类表演式认同；直接说明已核实的事实、准备做的改动或技术性反驳。
