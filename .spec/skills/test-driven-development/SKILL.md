# Test-Driven Development（务实 TDD）

## 必须优先测试的情况

- 新增核心运行时逻辑。
- 修复已复现 bug。
- 修改规则结算、数据加载、保存、生成、同步、UI 状态机。
- 变更第三方插件接入边界或项目正式入口。
- 同类错误已经复发。

## 可豁免的情况

- 纯文档、规范、索引或注释改动。
- 机械套用已有模式的小改动。
- 一次性取证脚本。
- Unity 资产或场景小调整，但仍必须有对应静态或 Editor 验证。

## 流程

1. 写最小失败测试或复现步骤。
2. 确认失败原因是目标行为缺失，不是测试写错。
3. 写最小实现。
4. 运行测试或验证，确认目标通过且没有回归。
5. 对无法自动化测试的 Unity 行为，用场景状态、Console、截图或资源检查替代，并说明限制。

## 禁止

- 为了测试而给生产代码加 test-only 方法。
- 只测 mock 行为，不测真实行为。
- 测试没复现用户原始症状却声称 bug 已修。
