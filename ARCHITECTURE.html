行动为什么不直接修改世界？

作者源 ActionDefinition 只声明参与槽位、条件和结果意图。真正提交发生在牌桌：先从请求重建候选，再冻结结果计划，完成后由 ActionResultSettlement.Commit 一次性改卡牌、装备、发现、货币等事实。

ActionDefinition -> ActionCandidate -> ActionInstance
  -> ActionResultSettlement.Compile(...)
  -> ActionInstance advances
  -> ActionResultSettlement.Commit(...)
  -> ScenarioRun.OnActionCompleted(...)
  -> QuestLog.RecordFact(...)

存档保存哪些事实？

ScenarioRunSnapshot 保存剧本 ID、内容集合、Mod 包、当前地区、每个地区牌桌、发现内容、任务日志、下一卡牌 ID、回合与时间推进状态。牌桌快照保存卡牌状态、活动行动和权威随机状态；当前实现明确拒绝保存战斗中状态。

表现层为什么不是第二套玩法状态？

TabletopView 绑定当前牌桌，监听 ActionSettled 和 PresentationCueRequested，再订阅 EX-GAS 伤害表现事件。悬浮、选择、卡牌表现和命中数字都是投影，不回写规则真相。

Tabletop owns rules
TabletopView binds Tabletop
  refresh when Cards.Revision or BattleRevision changes
  play presentation cues
  show hit result from EX-GAS presentation event

证据账本

所有重要结论都能回到源码或项目规范。右侧列表会跟随搜索过滤。

核心结论

  • Unity 工程版本是 6000.5.4f1，来自 ProjectSettings/ProjectVersion.txt:1。
  • Gameplay.Runtime 是玩法程序集，依赖 GameCore、EX-GAS、YokiFrame、Input System、URP、UniTask 等。
  • ScenarioDirector 是进程级剧本编排入口，ScenarioRun 是单局聚合。
  • Tabletop 是牌桌聚合根，QuestLog 是任务状态唯一写入口。
  • TabletopView 和 Scenario UI 是表现投影，不是规则 owner。
