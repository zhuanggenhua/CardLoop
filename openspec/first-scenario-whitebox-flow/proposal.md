# 首个白盒剧本流程提案

## 目标

先做一个能验证核心玩法的最小内置剧本：玩家看到角色、地点和资源卡，派角色去地点行动，行动完成后翻出新牌或推进任务。所有图片先用空白占位图加文本，不做正式美术，不做关卡编辑器。

## 参考取舍

- 采用《死亡寒冬：漫漫长夜》的结构内核：基地/队伍、外部地点、幸存者分配、搜索或事件、阶段目标。
- 不采用它的噪音、丧尸骰、隐藏背叛者、复杂殖民地危机。
- 吸收末日路线感：车辆和路线分支先作为“可发现地点/行动结果”表达，不单独开第二剧本。
- 部落与弯刀 Mod 文档只作为后续作者工具压力源：未来要能支持剧情、地图、事件和脚本扩展；本切片不接 Lua。

资料依据：

- 部落与弯刀 Mod 文档：https://blywd.hanjiasongshu.com/mod/
- Dead of Winter: The Long Night 规则参考：https://www.rulespal.com/dead-of-winter-the-long-night/rulebook

## 核心循环

1. 开局生成基地、2 名角色、2 个地点、1 个短任务。
2. 玩家把角色卡拖到地点卡或工位卡上。
3. 选择一个行动：探索、搜刮、修理、休整。
4. 回合推进，行动完成。
5. 行动结果生成资源、新地点、事件或任务进度。
6. 玩家根据新牌继续分配下一轮行动。

## 最小剧本

题名：`寒夜撤离`。

玩家目标：在废弃服务区集结幸存者，修好一辆可离开的车。

首轮内容：

- 角色：队长、技工。
- 基地：服务区营地。
- 地点：便利店、修车棚。
- 资源：罐头、燃油、零件。
- 事件：路障、求救信号。
- 任务：找到燃油 1、找到零件 1、完成修车 1。

## 必建缺口

| 顺序 | 缺口 | 最小做法 |
|---:|---|---|
| 1 | 剧本开局初始牌桌内容 | 在 `ScenarioDefinition` 或地区作者源中增加初始卡牌放置列表，只保存内容 ID、数量、位置和是否锁定。 |
| 2 | 白盒卡面 | 建一个项目正式占位 Texture/Material，让缺图内容也能被明确识别为白盒占位，而不是资源缺失。 |
| 3 | 地点/工位表达 | 先用普通 `CardDefinition` 表达地点卡；工位不新建系统，先由行动槽位和卡牌标签匹配承载。 |
| 4 | 探索/搜刮结果 | 复用现有行动结果意图和卡牌加权产出；缺什么补强类型，不新建事件系统。 |
| 5 | 任务完成 | 复用现有任务日志和任务子项：拥有卡牌、完成行动、探索卡牌。 |
| 6 | 后续编辑器字段记录 | 制作剧本时记录真实需要编辑的字段，等首个剧本跑通后再做 UI Toolkit 编辑器。 |

## 模块实施顺序

1. 抽象层：补齐“开局把哪些卡放到哪个地区牌桌”的作者源和运行时消费入口。
2. 内容层：制作白盒占位资源、角色、地点、资源、事件、行动、任务、剧本资产。
3. 运行层：让 `ScenarioDirector` 启动后自动把初始卡放进初始地区牌桌。
4. 表现层：确认空白卡面加文本可读，不因缺正式图片阻塞流程。
5. 验证层：从标题或测试入口启动剧本，完成一次“派角色探索 -> 获得资源 -> 任务推进”。
6. 记录层：写下本剧本实际使用字段，作为关卡编辑器第一版范围。

## 技术裁决

- 现在不用 Lua：首个切片只验证玩法结构，脚本层会引入权限、版本、存档和联机边界，过早。
- 现在不做关卡编辑器：先用真实内置剧本倒推出字段，避免工具先行。
- SO 不是教条：内置 Unity 作者流程和资源引用先用 ScriptableObject；后续 Mod 包、外部作者和批量数据再按生产方式选择 JSON/YAML/表格/脚本。
- UI Toolkit 暂只作为未来 Unity Editor 工具候选；当前玩家运行时 UI 不因本提案改变。

## 验收

- 能启动 `寒夜撤离`。
- 牌桌上能看到白盒角色、地点和资源文本。
- 玩家能完成一次地点行动并生成新牌。
- 任务日志能显示并推进至少一个目标。
- 提交一份“关卡编辑器第一版字段清单”，但不实现编辑器。
